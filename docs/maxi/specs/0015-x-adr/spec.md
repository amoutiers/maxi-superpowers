# Feature Specification: Recording Architecture Decision Records (x-adr)

x-adr is an internal pipeline skill — invoked by `/maxi:plan` and `/maxi:implement`, never by the user directly and absent from the `/maxi:*` command menu. When a calling skill detects an architectural decision worth recording (one that is costly to reverse, constrains future choices, or was contested because a real alternative was weighed), x-adr drafts an Architecture Decision Record from a template, checks it against existing accepted ADRs for contradictions, shows the full draft to the user, and writes an append-only `NNNN-slug.md` file plus a regenerated index only after explicit consent. Its defining behaviour is the consent gate: no file is ever written silently, and the calling skill's own detection does not substitute for user approval.

## User Scenarios & Testing

### User Story 1 - Capture a new architectural decision with consent (Priority: P1)

During planning or implementation, the agent detects an architectural choice worth recording and uses x-adr to draft an ADR, present it, and write it only after the user says `yes`.

**Why this priority**: This is the skill's primary reason to exist — turning a detected decision into a durable, consented record. Without it the skill does nothing.

**Independent Test**: With `docs/maxi/constitution.md` present, trigger x-adr from a plan that weighed two real options. Verify a full ADR draft is shown, the user is asked `Record this as ADR-NNNN? (yes / no / edit)`, and on `yes` a `docs/maxi/adr/NNNN-slug.md` file is written with `status: accepted` and the README index is regenerated.

**Acceptance Scenarios**:

1. **Given** `docs/maxi/constitution.md` exists and `docs/maxi/adr/` is empty, **When** x-adr drafts a decision, **Then** the ADR is numbered `0001` (zero-padded 4 digits).
2. **Given** `docs/maxi/adr/` already contains `0001-*.md` and `0003-*.md`, **When** x-adr computes the next number, **Then** it assigns `0004` (highest + 1, max-based not count-based, surviving deletions).
3. **Given** a drafted ADR, **When** it is shown to the user, **Then** no file has been written yet and the agent waits for an explicit response.
4. **Given** the user replies `yes`, **When** x-adr writes the file, **Then** the ADR frontmatter `status` is set to `accepted` and `docs/maxi/adr/README.md` is regenerated by scanning all ADR files sorted by number ascending.
5. **Given** the user replies `edit`, **When** they supply amendments, **Then** the amendments are applied inline to the draft and the amended version is written.

### User Story 2 - Refuse to write without explicit consent (Priority: P1)

The skill must never create an ADR file based on inference, ambiguity, or the calling skill's detection alone.

**Why this priority**: The Iron Rule ("Never Write Without Consent") is the skill's core safety guarantee. Violating it produces records the user never approved.

**Independent Test**: Trigger x-adr and reply with `no`, then separately with an ambiguous response like `looks good`. Verify no file is created in either case.

**Acceptance Scenarios**:

1. **Given** a drafted ADR, **When** the user replies `no`, **Then** the draft is discarded, no file is created, and control returns to the calling skill.
2. **Given** a drafted ADR, **When** the user replies with silence, `ok`, `sure`, `looks good`, `cancel`, `skip`, or any ambiguous text, **Then** it is treated as `no`, nothing is written, and the question is re-asked once: `To confirm: skip recording this decision? (yes to record / no to skip)`; if still ambiguous, treated as no and the skill moves on.
3. **Given** the calling skill already "made the decision explicit" or "the user asked me to record it," **When** x-adr runs, **Then** it still shows the draft and still asks — those rationalizations do not count as consent.

### User Story 3 - Detect contradictions and propose a supersede (Priority: P2)

Before drafting, x-adr loads existing accepted ADRs and surfaces any domain overlap to the user rather than deciding silently whether decisions conflict.

**Why this priority**: Keeps the ADR log coherent over time, but depends on a base of accepted ADRs existing, so it is secondary to capture and consent.

**Independent Test**: With an accepted ADR in the same technology domain (e.g., storage), trigger x-adr for a conflicting choice. Verify the draft is framed as a supersede proposal referencing the prior ADR.

**Acceptance Scenarios**:

1. **Given** an existing accepted ADR-003 in the same domain, **When** x-adr detects overlap, **Then** it presents the new draft with the header `This decision appears to contradict ADR-003 ("original title"). Propose ADR-NNNN that supersedes ADR-003?` and lets the user decide.
2. **Given** the user approves a supersede, **When** x-adr writes, **Then** it writes the new ADR, sets the old ADR's `status: superseded` and `superseded_by: NNNN`, and regenerates the index; if any of the three writes fails it stops and reports rather than leaving a partial state.

### User Story 4 - Preserve append-only immutability (Priority: P2)

Once an ADR is written its body and identifying fields are immutable; only lifecycle fields may change.

**Why this priority**: Protects the historical-record integrity of the log, but applies only after records exist.

**Independent Test**: Ask x-adr to edit an existing ADR's Context section. Verify it declines and offers to create a superseding ADR instead.

**Acceptance Scenarios**:

1. **Given** a written ADR, **When** the user asks to edit its body, **Then** the skill declines: `ADRs are append-only. To revise this decision, I can create ADR-NNNN that supersedes ADR-NNNN. Shall I?`
2. **Given** a written ADR, **When** its lifecycle changes, **Then** only `status`, `superseded_by`, and `supersedes` may be updated — never any body section or `adr`/`slug`/`created`/`related_*` fields.

### Edge Cases

- **Missing constitution**: If `docs/maxi/constitution.md` does not exist, the skill stops immediately with `No constitution found. Run /maxi:constitution first.` before doing anything else.
- **Missing template**: If `adr-template.md` cannot be read, the skill stops: `Cannot proceed — adr-template.md is missing. Please reinstall the maxi plugin.`
- **Decision turns out not ADR-worthy / user declines consent**: On `no` or ambiguous response, the draft is discarded with no file written and control returns to the caller.
- **Empty related_specs in index**: The index cell is written as `—` rather than left empty.
- **Deleted or manually renumbered ADRs**: Max-based numbering ensures the next number does not collide even after deletions or manual additions changed the file count.

## Requirements

### Functional Requirements

- **FR-001**: x-adr MUST be an internal pipeline skill invoked by `/maxi:plan` and `/maxi:implement`, not by the user, and MUST NOT appear in the `/maxi:*` command menu. (skills/x-adr/SKILL.md:10)
- **FR-002**: Before any other action, x-adr MUST verify `docs/maxi/constitution.md` exists and stop with `No constitution found. Run /maxi:constitution first.` if it is missing. (skills/x-adr/SKILL.md:18)
- **FR-003**: x-adr MUST show the full drafted ADR and receive an explicit `yes` (or `edit`) before writing any file. (skills/x-adr/SKILL.md:23)
- **FR-004**: x-adr MUST NOT treat the calling skill's detection of the decision as user consent to write. (skills/x-adr/SKILL.md:25)
- **FR-005**: x-adr MUST reject the rationalizations "the plan made the decision explicit," "the context was clear enough," and "the user asked me to record it," and still show the draft and ask. (skills/x-adr/SKILL.md:27)
- **FR-006**: x-adr MUST compute the next number by scanning `docs/maxi/adr/` for `NNNN-*.md` files (excluding `README.md`), taking the highest numeric prefix + 1, zero-padded to 4 digits; if no matching files exist NNNN = 0001. (skills/x-adr/SKILL.md:72)
- **FR-007**: x-adr MUST use max-based numbering (not count-based) so deletions, renames, or manual additions do not cause collisions. (skills/x-adr/SKILL.md:74)
- **FR-008**: x-adr MUST read every accepted ADR and scan Decision sections for domain overlap with the new decision (same technology category: storage, runtime, framework, auth, etc.). (skills/x-adr/SKILL.md:78)
- **FR-009**: x-adr MUST surface any domain overlap to the user and MUST NOT decide silently whether two decisions are contradictory. (skills/x-adr/SKILL.md:80)
- **FR-010**: x-adr MUST verify `adr-template.md` exists before drafting and stop with `Cannot proceed — adr-template.md is missing. Please reinstall the maxi plugin.` if absent. (skills/x-adr/SKILL.md:84)
- **FR-011**: x-adr MUST use `adr-template.md` as the base for the draft and fill in all frontmatter fields (`adr`, `slug` as `NNNN-[short-kebab-title]`, `status: proposed`, `created`, `updated`, `decider`, `related_specs`, `related_principles`, `related_requirements`, `supersedes`, `superseded_by: null`). (skills/x-adr/SKILL.md:86)
- **FR-012**: x-adr MUST fill all six body sections — Context, Decision Drivers, Considered Options, Decision, Consequences, Confirmation. (skills/x-adr/SKILL.md:100)
- **FR-013**: x-adr MUST list 2–4 decision drivers derived from constitution principles, spec requirements (FR-###/SC-###), or explicit plan constraints, and MUST never leave Decision Drivers empty. (skills/x-adr/SKILL.md:103)
- **FR-014**: x-adr MUST annotate each considered option with ✅/❌ lines that reference a specific driver, not generic pros/cons. (skills/x-adr/SKILL.md:108)
- **FR-015**: When a contradiction is found, x-adr MUST frame the draft as a supersede proposal with the header `This decision appears to contradict ADR-003 ("original title"). Propose ADR-NNNN that supersedes ADR-003?`. (skills/x-adr/SKILL.md:119)
- **FR-016**: x-adr MUST output the full ADR as formatted Markdown and ask `Record this as ADR-NNNN? (yes / no / edit)`, then wait without writing. (skills/x-adr/SKILL.md:125)
- **FR-017**: On `yes` (normal case), x-adr MUST set `status: accepted`, write `docs/maxi/adr/NNNN-slug.md`, then regenerate the index. (skills/x-adr/SKILL.md:134)
- **FR-018**: On `yes` (supersede case), x-adr MUST write the new ADR, set the old ADR's `status: superseded` and `superseded_by: NNNN`, regenerate the index, and stop reporting failure if any of the three writes fails rather than leaving a partial state. (skills/x-adr/SKILL.md:135)
- **FR-019**: On `edit`, x-adr MUST accept amendments inline, apply them, and write the amended version under the normal or supersede rules. (skills/x-adr/SKILL.md:137)
- **FR-020**: On `no`, x-adr MUST discard the draft, create no file, and return to the calling skill. (skills/x-adr/SKILL.md:142)
- **FR-021**: On silence, `ok`, `sure`, `looks good`, `cancel`, `skip`, or ambiguous text, x-adr MUST treat the response as `no`, write nothing, re-ask once with `To confirm: skip recording this decision? (yes to record / no to skip)`, and if still ambiguous treat as no and move on. (skills/x-adr/SKILL.md:145)
- **FR-022**: After every successful write, x-adr MUST regenerate `docs/maxi/adr/README.md` by scanning all `.md` files (excluding `README.md`), sorting by ADR number ascending, and reading each file's frontmatter for table values. (skills/x-adr/SKILL.md:150)
- **FR-023**: The regenerated index Status column MUST reflect the current frontmatter value (including `superseded` or `deprecated`) and MUST NOT default to `accepted`. (skills/x-adr/SKILL.md:150)
- **FR-024**: When `related_specs` is empty, x-adr MUST write `—` in the index cell rather than leave it empty. (skills/x-adr/SKILL.md:161)
- **FR-025**: After creation, an ADR's content MUST be immutable; only `status`, `superseded_by`, and `supersedes` MAY be updated. (skills/x-adr/SKILL.md:165)
- **FR-026**: x-adr MUST NOT edit any body section or the `adr`/`slug`/`created`/`related_specs`/`related_principles`/`related_requirements` fields of an existing ADR. (skills/x-adr/SKILL.md:170)
- **FR-027**: When asked to edit an existing ADR's body, x-adr MUST decline with `ADRs are append-only. To revise this decision, I can create ADR-NNNN that supersedes ADR-NNNN. Shall I?` and offer to supersede instead. (skills/x-adr/SKILL.md:176)

### Key Entities

- **ADR file** (`docs/maxi/adr/NNNN-slug.md`): YAML frontmatter with `adr`, `slug` (`NNNN-[short-decision-slug]`), `status` (`proposed` → `accepted` → `superseded`/`deprecated`), `created`, `updated`, `decider`, `related_specs`, `related_principles`, `related_requirements`, `supersedes`, `superseded_by`; followed by six body sections: Context, Decision Drivers, Considered Options, Decision, Consequences, Confirmation. (skills/x-adr/adr-template.md:1)
- **ADR template** (skill-local `adr-template.md`): the canonical base from which every drafted ADR is filled; presence is a precondition for drafting. (skills/x-adr/adr-template.md:16)
- **ADR index** (`docs/maxi/adr/README.md`): a Markdown table with columns ADR (linked), Title, Status, Created, Related Specs, sorted by ADR number ascending; regenerated after every successful write. (skills/x-adr/SKILL.md:152)

## Success Criteria

### Measurable Outcomes

- **SC-001**: No ADR file is ever created without the user having seen the full draft and replied `yes` or `edit` — 100% of writes are consent-gated.
- **SC-002**: Every drafted ADR uses `adr-template.md` as its base and contains all six body sections fully filled (none left as template placeholders).
- **SC-003**: ADR numbers are unique and monotonic under max-based assignment even after files are deleted or manually renumbered (0% collision).
- **SC-004**: After every successful write the index in `docs/maxi/adr/README.md` lists all current ADRs sorted ascending with Status matching each file's live frontmatter.
- **SC-005**: Existing ADR bodies and identifying frontmatter fields are never modified; all revisions are expressed as new superseding ADRs.
- **SC-006**: When a decision overlaps an existing accepted ADR's domain, the overlap is surfaced to the user in 100% of cases rather than resolved silently.

## Assumptions

- The skill is always entered from a calling skill (`/maxi:plan` or `/maxi:implement`) that has already detected a recordable architectural decision; x-adr does not perform the detection itself.
- `docs/maxi/constitution.md` and `adr-template.md` are the only hard preconditions; absence of either halts the skill with a fixed message.
- The user is the authority on whether two same-domain decisions actually contradict; the skill defers this judgment to them.
- ADRs are stored as flat Markdown files under `docs/maxi/adr/` with a sibling `README.md` index in the same directory.
- "Today" for `created`/`updated` is the current date supplied to the agent at run time.
